# @agyhq/hooks

Lifecycle hook scripts that `agy` (Antigravity CLI) invokes directly, plus
the TypeScript they're built from. These are the only part of agy-hq that
runs *inside* an `agy` process, wired in via each workspace's
`.agents/hooks.json`.

## Purpose

- **`pre-tool-use`** — the only real safety gate. Calls the agy-hq daemon's
  policy endpoint before every tool call and fails closed (deny) on anything
  that isn't a clean `allow`.
- **`audit`** — best-effort activity log for `PostToolUse` and
  `PostInvocation`. Never blocks the run; spools to disk if the daemon is
  unreachable.
- **`context`** — injects per-conversation context (CRM/task notes) into the
  model via `PreInvocation`, capped in size. Injects nothing on failure.
- **`stop`** — lets the daemon force the agent to keep going (`continue`) or
  confirms a real stop, with a built-in loop guard so a daemon bug can never
  make the agent run forever.

See `docs/PHASE0.md` D3/D5 and `spike/03-hooks/FINDINGS.md` for why each hook
behaves this way (fail-open vs fail-closed is not a style choice — it's the
only thing standing between agy-hq and either a broken outbound gate or a
run that quietly loops forever).

## Public API (`src/index.ts`)

```ts
import {
  // Hook payload/response types (ported from spike/03-hooks/hook-types.ts,
  // corrected against observed payloads — see src/types.ts for the diffs).
  type PreToolUseInput, type PreToolUseOutput,
  type PostToolUseInput, type PostToolUseOutput,
  type PreInvocationInput, type PreInvocationOutput,
  type PostInvocationInput, type PostInvocationOutput,
  type StopInput, type StopOutput,
  type InjectStep, type TranscriptLine,

  // Pure mapping functions (payload -> @agyhq/core request, decision -> agy response)
  toPreToolUseRequest, toPreToolUseOutput, denyPreToolUse,
  toAuditRequest, AUDIT_NOOP_RESPONSE,
  toContextRequest, toContextOutput, NO_CONTEXT_RESPONSE,
  toStopRequest, toStopOutput, PLAIN_STOP_RESPONSE,

  // Env
  readHookEnv, type HookEnv,

  // HTTP
  postHook, HookRequestError, type HookRequestErrorCode,

  // stdin
  readHookPayload, readStdin,

  // Audit spool (fail-open backstop)
  auditSpoolPath, spoolAuditRequest, AUDIT_SPOOL_RELATIVE_PATH,

  // Stop loop guard
  stopGuardPath, readStopGuardCount, writeStopGuardCount, clearStopGuard,

  // Canonical dist filenames
  HOOK_SCRIPT_NAMES,
} from "@agyhq/hooks";
```

`HOOK_SCRIPT_NAMES` is the single source of truth for which built script
serves which agy event:

```ts
HOOK_SCRIPT_NAMES = {
  PreToolUse: "pre-tool-use.mjs",
  PostToolUse: "audit.mjs",       // invoked as `node audit.mjs PostToolUse`
  PreInvocation: "context.mjs",
  PostInvocation: "audit.mjs",    // invoked as `node audit.mjs PostInvocation`
  Stop: "stop.mjs",
}
```

## Build

```sh
npm run build   # from packages/hooks, or `npm run build --workspaces` from the repo root
```

Runs `esbuild.config.mjs`, which bundles each `src/bin/*.ts` entrypoint
(including `@agyhq/core` and `zod`) into a single dependency-free ESM file
in `dist/`. No `node_modules` needs to exist next to `dist/` at runtime —
a workspace's `hooks.json` can reference the built files by absolute path.

## hooks.json wiring (generated by the workspace package)

```json
{
  "agy-hq": {
    "PreToolUse":     [{ "matcher": ".*", "hooks": [{ "command": "node <dist>/pre-tool-use.mjs", "timeout": 10 }] }],
    "PostToolUse":    [{ "matcher": ".*", "hooks": [{ "command": "node <dist>/audit.mjs PostToolUse", "timeout": 5 }] }],
    "PreInvocation":  [{ "command": "node <dist>/context.mjs", "timeout": 5 }],
    "PostInvocation": [{ "command": "node <dist>/audit.mjs PostInvocation", "timeout": 5 }],
    "Stop":           [{ "command": "node <dist>/stop.mjs", "timeout": 10 }]
  }
}
```

## Runtime contract

Every script reads one JSON payload from stdin (the agy hook payload) and
writes one JSON response to stdout. Env vars (inherited from the `agy`
process the runner spawned — see docs/PHASE0.md D2) read by every script:

| Var | Required | Used for |
|---|---|---|
| `AGYHQ_API_URL` | yes | daemon base URL |
| `AGYHQ_TOKEN` | yes | `Authorization: Bearer <token>` |
| `AGYHQ_AGENT_ID` | yes | `x-agyhq-agent-id` header |
| `AGYHQ_TASK_ID` | no | `x-agyhq-task-id` header, if present |

Missing a required var is treated as a hook failure (deny for
`pre-tool-use`, no-op/spool for the others — never a crash with no stdout).

### `pre-tool-use.mjs` — FAIL-CLOSED

POSTs `HOOK_ROUTES.preToolUse` with a 5s timeout. Denies (prints
`{"decision":"deny","reason":"..."}`) on: missing env, unparsable/empty
stdin, network error, timeout, non-2xx status, or a response that isn't a
valid `ApiEnvelope`. The reason string always explains briefly why — the
model sees it verbatim (confirmed in spike 03 Q2). A clean `allow` decision
maps straight through, including `allow` + `overwrite`.

### `audit.mjs <PostToolUse|PostInvocation>` — FAIL-OPEN

Always prints `{}` (bounded by a 2s POST timeout to `HOOK_ROUTES.audit`).
If the POST fails for any reason (including missing env), the request is
appended as one JSON line to `<cwd>/.agyhq/audit-spool.jsonl` (directory
created if needed) so the daemon can ingest it later.

### `context.mjs` — FAIL-OPEN

POSTs `HOOK_ROUTES.context` with a 3s timeout. Each string in the
response's `messages[]` becomes one `injectSteps[].ephemeralMessage` entry,
in order, capped at **4,000 total characters** — a message that would cross
the cap is truncated with `...` and no further messages are added after it.
Any failure (including missing env) returns `{}` — no injection, never
blocks the model call.

### `stop.mjs`

POSTs `HOOK_ROUTES.stop` with a 5s timeout. On success, `{decision:"stop"}`
maps to `{}` (let it really stop) and `{decision:"continue", reason}` maps
through unchanged. On any failure, falls back to a plain stop — it never
lets a broken daemon loop the agent forever.

**Loop guard**: independent of what the daemon says, this hook will force a
real stop after **2** forced continuations for a given `conversationId`. It
uses `StopInput.executionNum` (increments each time the loop tries to stop,
*within one `agy` process*) **and** a small per-conversation counter file
under `<cwd>/.agyhq/stop-guard-<conversationId>.json`, taking whichever is
higher. The file exists because a resumed task (`--conversation <id>` in a
fresh `agy` process, per docs/PHASE0.md D2) resets `executionNum` back to 0,
so `executionNum` alone can't catch a daemon that keeps saying "continue"
across separate task runs for the same conversation.

## Tests

```sh
npx vitest run packages/hooks
```

- `test/mapping.test.ts` — unit tests for the pure mapping functions, using
  real captured payloads from `spike/03-hooks/raw/*` as fixtures (copied into
  `test/fixtures/`; the `call_mcp_tool` fixture is synthesized from the
  `{ServerName, ToolName, Arguments}` shape observed in
  `spike/02-workspace-agents/raw`, since spike 03 never exercised MCP).
- `test/integration.test.ts` — spawns the **built** `dist/*.mjs` scripts as
  real child processes against a local mock HTTP daemon
  (`test/mock-daemon.ts`, Node builtins only). Covers allow / deny /
  allow+overwrite, daemon-down, timeout, invalid envelope, non-2xx, bad
  stdin, missing env, the audit spool, context injection + size cap, and the
  stop continue/stop + loop-guard paths (including the cross-process guard
  file). Run `npm run build` first — these tests fail fast with a clear
  message if `dist/` is stale or missing.
- `test/real-agy.test.ts` — **opt-in**, costs real model time:
  ```sh
  AGYHQ_REAL_AGY=1 npx vitest run packages/hooks/test/real-agy.test.ts
  ```
  Builds a temp workspace with `.agents/hooks.json` pointing at the built
  dist scripts, starts a mock daemon that denies `run_command`, and asks the
  real `agy` CLI (`gemini-3.8-flash-low`, `--dangerously-skip-permissions`)
  to run `echo hi`. Asserts the mock daemon received a `run_command`
  `PreToolUse` request and that agy's stream-json output shows the tool call
  was denied (`"...denied by pre-tool hook..."`), never a successful echo.
  **Verified passing** against `agy` 1.2.14 in this environment.

## Deviations / notes for the daemon implementer

- `PostToolUseOutput`/`PreInvocationOutput` etc. accept any JSON object;
  agy ignores unknown keys (per `hooks.md` and spike 03 observations), so
  these hooks don't need to match the doc's shapes exactly — only
  `PreToolUseOutput.decision` and `StopOutput.decision` are semantically
  load-bearing.
- No core contract changes were needed. `PreToolUseRequest.parameters` is
  exactly `toolCall.args` from the agy payload — for `call_mcp_tool` that is
  `{ServerName, ToolName, Arguments}`, matching the shape already documented
  in `packages/core/src/api.ts`.
- `StopRequest.payload` is the raw `StopInput` from agy (cast through
  `Record<string, unknown>`), in case the daemon wants fields beyond the
  three pulled out explicitly (`transcriptPath`, `terminationReason`,
  `conversationId`) — e.g. `fullyIdle` or `executionNum` for its own
  checkpointing logic.
